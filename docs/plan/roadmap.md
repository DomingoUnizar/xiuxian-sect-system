# 路线与放行条件

顺序为 **M0 能启动 → M1 决定留下后果 → M2 多次回来仍有新意 → M3 长档与规模可信 → M4 可发布**。M1 是第一道产品立项门槛。工单可合并或拆小，阶段结束要有稳定提交、能复玩的入口、验收证据和回退路径。

| 阶段与玩家体验 | 核心工作、依赖与复用 | 客观门槛和实际检查 | 主要风险、高级复核与回退 |
| --- | --- | --- | --- |
| **M0 · 起步**。玩家能从固定入口打开中文山门，辨认人物和药谷。 | 依赖本规划分支。Neon + Hydrogen 完成 N0 和 N1 起点。Vite、Vue、固定种子、两项政策命令、试存一个本地槽。UI Skill 用已有药谷、肖像、青玉。本轮校样供对照。 | 在第二工作副本按记录启动并构建。移动／桌面读到标题、人物，关闭重开读回相同 ID。无界面推进两次得到同一哈希。记录 Node 版本、锁文件和访问地址。 | 风险是脚手架花太久。限定一个小验证，过期即收缩工具选型。只有 Worker／存储契约在目标设备走不通才请高级模型。提交入口与基线，上游回退到规划提交。 |
| **M1 · 药谷切片**。一包药、一份赏额、两个目标，玩家经历委托、放手、回归与第二次决定。 | 依赖 M0。六人、两地、两种敌性、两个可相互影响的技法、三条事件链、五类战果、保守离线默认、快照与战报。Hydrogen 串主线，Neon 独验。用玩法与 QA Skills、真素材、Vitest / Playwright。 | 完成下文 A/B、无干预、离线及盲测四项。六人离线 8 小时在记录的基准手机环境上补算 p95 目标 ≤2 秒。普通分片推进期间滚动仍可响应。 | 最怕两个按钮只换一段话。若两轮改动后仍无法从一次决策追到另一人的后继机会，请 Astra 等一位做玩法复核。每条竖向功能独立提交，过门后记录 M1 提交与成对存档。失败保留证据，回到最近通过的切片。 |
| **M2 · 可复访的小宗门**。玩家在第二天认出旧人情，在第三次回山看到第一代弟子把能力传下去。 | 依赖 M1 体验过关。扩展岗位／师承、弟子继任、人情与一次邻宗借药。先补在样本里沉寂的事件族，再引入一条受审的系统例外。DeepSeek 做批量夹具和统计，Hydrogen 整合。复用现有同系列头像、三两处场景与短音。 | 选 3 名观察者做 3 次分开回访，跨度至少 48 小时。至少 2 人能指出第一回的决定怎样影响第三回。做 30 小时等价仿真，比较重复与覆盖，下列长线指标达标再扩区。 | 风险是内容疲劳和稀有通胀。先改触发条件或后果。大范围改概率仍只靠固定奇遇撑场时才升级设计复核。内容包版本单独提交，可以退回 M1 内容包及配套存档。 |
| **M3 · 邻宗与长期世界**。旧弟子退居授业，邻宗会记得上回借出的药。关注对象和宗门数增加后仍能找回旧事。 | 依赖 M2。加入地方势力承诺、资源守恒、人物冷热分层、历史索引、迁移与补算。仅实现 v0.7 已明确的阵营关系，独立执法堂与分层正道盟保留接口。远方势力先按期结算。Hydrogen 管内核／旧档。DeepSeek 跑压力种子，Profiler 只针对实测瓶颈。 | 百名活跃弟子离线 24 小时，在记录机型的中端 Android 浏览器 p95 目标 ≤5 秒。千人含远方摘要跑 7 日离线，期间可查上次纪事，有进度可中断续算。迁移黄金档、双标签竞争、空间不足、写盘中断和归档父因全过。iOS Safari 和 Android 真机各走一次打开、切后台、恢复、导入流程。 | 风险是负库存、旧档丢失和世界切层双算，任一发生立即停扩张并请一位架构复核。改档前双槽备份、记录恢复演练。回退旧构建配旧快照，保留新档供诊断。 |
| **M4 · 首次公开版**。玩家能在手机打开发布地址、恢复并导出自己的宗门史，更新后接着玩。 | 依赖 M3。Neon 做独立发布清单，Hydrogen 只修阻断项。静态托管、版本化资源路径、离线／更新提示、音频解锁、归档导出、授权台账。复用 QA Release、现成图集和已确认可外发的素材。 | 用实际候选构建在目标托管子路径加载、断网重开（若承诺全离线启动，要验证预缓存）、更新、恢复旧档和重新导入。审查所有分发资产、署名文件、手机首屏与真实试听。保存构建校验和、trace、机型和回滚演练。 | 风险是缓存跨版、字体过大、未获授权的 UI 进入公开包。用固定资源清单与旧静态包回退。只为未解的分发或兼容问题升到相应负责人。发布与合并稳定分支须另有实际验证和授权。 |

## M1 的完整验收

1. **同一起点只改一项政策。** 冻结初始档、种子、内容／规则／RNG 版和终点时刻。A 选接应，B 选取样。两边都让弟子自行跑完，政策后不追加干预。分别导出原档与验收投影。每边至少有三条连得上的事实，验证药包所在、伤势／关系和一个可执行的后继机会。至少一个普通弟子因此成为传路、授艺或救援的关键人物。换种子可有别的故事。验收种子事先登记，失败种子保留。
2. **零操作也会生活。** 同初态完全不接单，连续推进一个窗口。必须有人修炼或工作，有人休息／交往，有平凡事件自动结案。故意使首选人重伤或拒绝，系统能换人、等候或让机会过期，并显示理由。无预警、无风险授权时的普通战败不得致死。用专用险境夹具另验严重失败、获救及死亡留痕。
3. **自动战报与离线可信。** 普通路径从真实入口完成“下政策 → 关页 → 重新打开 → 看纪事 → 展开战报 → 查看人物／库房 → 再下政策”。用可控时钟测八小时、随机切片及写盘中断，再让一个真实存档跨一次实际关页离线时段，分别记时长和方式。展开、跳过、刷新各三次，资源与关系只落一次。种子批跑检查常规实力差与例外条件，不能让无路标的人借西径撤退、没佩戴的法宝出手。提交、构建、tests、trace 与两尺寸可玩截图归档。
4. **独立试玩与人是否愿意回来。** Neon 或另一位未写该功能的验收者，从首次访问盲玩默认路径。再请至少三位首次接触者各玩 15～25 分钟，先别解释公式。记录“你把奖赏留给谁，牺牲了什么”“这是谁造成的”“下次想看谁”。至少两人能独立从纪事指出一条三步因果，讲出一名普通弟子的独特作用，并针对新局势作出下一项选择。至少两人自发点名想追看的后续。记录没有回看的理由。小样本只决定是否值得投资下一步，真实复访在 M2 验证。

**失败时改什么。** 两项政策总选同一边，检查另一边是否有独占的机会与可见代价。人记不住弟子，先让同一个人落入两次有关联的抉择。回归纪事没人展开，把一条“因为／因此／现在可以”提到第一屏。每次只改一个关键假设，复跑原种子及新种子，留下前后两份体验记录。机器证据全绿、真人未招募时可继续修复和测试，M1 乐趣门槛留在待验。

## 长期检查和风险处置

| 风险或待决问题 | 如何判定、何时作决定 |
| --- | --- |
| 同套路占优、随机奖压过人物 | 用至少 200 个配对种子比较两项政策的药量、伤休时长、路线传授与取样情报。两边应各有一个可解释的优势维度。在预登记的雾重／药荒两种情境下，首选策略应随目标变化。稀有机缘关闭时照样完成首局。 |
| 数十小时变成重播 | M2 检查各档最近 20 条头条，单模板占比目标 ≤30%，同一师徒／救援桥段要有真实状态改变才能重现。统计没有后继的重点事件和无人被关注的弟子。3 次复访既看频率也读玩家口述，频率均匀不能代替好玩。 |
| 模拟与表现成本偏高 | M1 首屏传输量目标 ≤1.5 MiB（压缩冷缓存，独立记 JS、图像、字体）。先正文与可操作项，再载背景和声音。100 次页面／补算采样或注明较小样本量，区分机器、视口模拟与真机。动画打开与关闭的世界哈希应相等。 |
| 世界边界与名称 | 已确认 v0.7、世界名、系统身份、稀有特例、修炼难度。系统细节、宗门以外能否察觉、命名由用户与世界维护者决定。首版用宗门内秘密委托、预先有修行经历的角色、保守离线政策继续推进。 |
| 素材可外发、设备存储与付费能力 | 已核实清单、部分具体工具调用和桌面浏览器校样。公开分发青玉 UI 的权利、实际音色、iOS 体验、磁盘外备份与跨平台模型权限仍各有验证责任。对应项可用系统字体、已许可素材、文本反馈或手动交接继续开发。 |
| 证据与现实的边界 | 当前已有 Git 资料基线、规划、桌面／手机静态校样、工单检查器。缺少游戏构建、实际双档、离线收益、性能样本和玩家观察。每次晋级在工单中写证据文件、提交与复测入口。 |

首版工单与启动顺序见 [Neon 开工入口](README.md)。任何未达门槛的阶段都保留最近已验证成果。继续迭代的优先依据是玩家能否察觉自己的决定怎样改变了某个人。
