# 路线与放行条件

玩家先招人、发出自己的第一道秘密任务，再在回山时看见宿主领取重赏。随着宗门真正培养出新人、传下新法，玩家获得更高权限。开发和验收都沿着这条循环安排，普通宿主始终能在无人操作时修炼、经营、赴擂或历练。

| 阶段 | 从正式入口实际玩到什么 | 完成证据 |
| --- | --- | --- |
| **M0 · 开山** | 从可复现的本地入口打开中文山门，看到本局生成的宗主、在籍门人及这届候选。重新打开仍认得同一批人 | 第二份干净工作副本能按说明启动和构建。留提交、启动方法、浏览器地址、生成种子和一次实际读档记录 |
| **M1 · 首令兑现** | 招徒入门即绑定。玩家亲发「首炼灵丹」或「擂上首胜」，宿主自主应令，离线也能达成并领取十轮修为。实力、库存或名望的变化会影响下一次机会。实际首成还可解锁首个进阶权限 | 跑通下面 N1～N4。交付派令至发奖的真实因果、同起点对照、离线与读档证据，以及独立试玩观察 |
| **M2 · 百艺与多人私令** | 新人带来不同养法，炼丹、炼器、御兽与秘境产物彼此可用。验证 5 点根基的规则赐予和 9 点的多人因果。已取得权限的宗门可在同一次大比分别悬赏突破、夺魁、护擂 | 验同一材料因两种已学手法产生不同产物，以及产物怎样被同门实际使用。大比中甲可完成突破后落败，乙与长老分别按胜负、护擂条件领赏。换种子可以换人、换结果。分开回访验证隐藏奖、传承与下一届招徒 |
| **M3 · 一宗多代** | 分院在外仍属同一宗门，正式退宗停止收新私令，弟子可接棒授徒。验证 14 点根基的宗门法则。以持有一次全宗灌顶赐福的「万剑归宗」为例，百日内迎经，三名原先不会首式的人独立练成，才触发全体在籍宿主的百轮灌注 | 验取经者先领奖、练成两人时尚在进行、第三人达成时全宗兑现。以达成时的在籍名单核账，外出和分院弟子同样计入。验证跨代历史、邻宗活动、存档迁移、大规模离线中断续算及真机回归 |
| **M4 · 可发布** | 手机从实际发布地址入宗，能在更新后接着玩、查看旧纪事、导出和恢复宗门 | 从候选构建验证静态路径、缓存更新、音频解锁、触控与恢复。在目标设备复玩，保存版本校验和、素材授权清单和已演练的回退入口 |

权限点数和性能值沿用本版设计的示例与实验目标。调整时同步玩法、技术契约和实际使用的基准档，并保留变更前的证据。[玩法设计](gameplay.md) · [技术契约](architecture.md)

## M1 开工单

本表是现行派工入口。N0 对应 M0，N1～N4 组成第一次完整游戏循环。Neon 统筹并安排独立复玩，默认由 Hydrogen 完成连续实现。每项完成后在功能分支留下提交、可运行入口和复现方式。

| 顺序 | 实现范围 | 交给下一项前要能实际观察到什么 |
| --- | --- | --- |
| **N0 · 能进山门** | 建立 Vue 3、TypeScript、Vite 正式入口、中文界面、最小模拟时钟、本地存读与可导出的初态。在项目记录依赖锁、启动和构建方法 | 从新工作副本打开可操作的山门。关页重开后，世界种子、当前时刻和已有成员身份延续 |
| **N1 · 招进可培养的人** | 从当前地域生成候选，试艺只揭示已有本领。玩家可亲选或让长老按偏好补席，候选可应邀或谢绝。正式入宗时建立唯一绑定 | 新种子能换一批资质与来历。同一届翻页、重开保留同一人。未入门者只收到公开邀请。新人一入门就能收到只对自己可见的任务 |
| **N2 · 派令、履约、立刻到账** | 让默认日常自行派发。玩家可给有条件的宿主发布首炼或首胜悬赏。记录明奖、预留、接受或推辞、行动判定、结算。让一枚实物丹药和一场真实擂台胜负都能进入后续玩法 | 看见“【叮！系统发布任务】”、宿主、目标及重赏。用正常模拟达成，直接取得修为。推辞或过期归还预留。用另一个宿主身份查看，只能看见自己的消息 |
| **N3 · 放置、归来、权限成长** | 接上挂机推进、回归摘要、任务与人物详情。支持一次可传的新本领被第二人独立复现，纳入道统首成，开放第一项常开悬赏 | 从真实关页前后的存档一路追到已发奖励和下一项可做的事。能从首成记录看到 2 点根基解锁自动悬赏，再发一条对后续新人有效的规则 |
| **N4 · 独立复玩** | 由未实现该功能的人从冻结提交进入，跑下述验收与反例，记录实际玩家怎么理解那声“叮”以及想把下份重赏给谁 | 两个分支的导出、检查结果、两尺寸截图、操作记录与试玩结论可定位到同一候选构建。复验发现的问题回到对应工单修复 |

## M1 验收

1. **新开一局就能做决定。** 走一次“开山 → 试艺 → 邀请 → 自愿入门 → 绑定 → 发布私令”。观察候选、在籍宿主和退宗者的边界。系统视角可追全宗私令，宿主视角只见自己的任务，公开纪事只写炼丹、出战、胜负等公开事实。用另一个种子再走一次，首道私令随本局人选与真实机会生成。
2. **同一名新人，换一道悬赏。** 从同一份入门后的存档分两支。预登记一个既能运丹火又能参加同境切磋的随机宿主，场上确有凡炉、材料和对手。A 悬赏「首炼灵丹」，B 悬赏「擂上首胜」。两边固定同一个人、同一份十轮修为、其余命令、世界时刻、种子和规则版本，只改任务目标。两档各自按真实规则跑完。选用能走通两种成功路径的基准种子，同时保留失败样本。核对 A 的成丹与实物去向、B 的实际胜场与已开放的复赛或挑战资格。每边从派令追到行动、发奖和一个能实际使用的后继机会。以常态每轮 8 缕为例，奖励本身的增量各为 80 缕，常规修炼另记。
3. **重奖确实只发一次。** 检查预留、兑现、释放和道统首成四类记录。记录宿主拒绝、期限内未成和挑战最终未获胜三种情况，核对未成原因与最终释放的预留。达成即发奖，随后同一招式、法器或修为增量可影响下一次行动。反复展开、跳过、刷新和重复投递同一命令后，奖励与道统都只计原来的一笔。若药材不够或对手缺席，门人仍可修炼、试艺或做其他有条件的日常任务。
4. **关页期间照常运转。** 实际从游戏入口关页、重开、看已发奖摘要、进宿主详情、再发一令。另用可控时钟比较在线推进、八小时离线、分片及写盘中断后的同一世界，核对库存、任务、奖励、根基、进行中的活动与随机状态。自动任务有依据，未完成的保留进度。普通战败按实际情况退走或养伤。另取严重失败或特殊险境的样本，验证可能死亡、法宝护主或获救的条件与留痕。
5. **权限有来处。** 另取一份可复演的传承形成前存档。先核对创法者会用、后学尚不会。推进到后学实际独立使出新法，验首成账与权限变化，再让下一位符合条件的新宿主收到常开悬赏。单人首次成丹本身只结首炼任务。
6. **玩家是否愿意回来。** 独立者先盲玩，再请至少三位首次接触者各玩 15～25 分钟。请他们指给你看哪道令是自己发的、谁收到什么、回来时宗门多了什么，以及下一次想重赏谁。体验目标为至少两人能独立从真实纪事指出一条因果，并凭已得奖励作出下一项选择。照实登记达标人数和没有继续追看的原因。真人观察和规则验证分别记状态，缺观察时保留待验项。[交接材料](workflow.md#交接证据)

## 长线验证与回退

| 要观察什么 | 用什么证据作判断 |
| --- | --- |
| 喜讯密度与重复游玩 | M2 做 30 小时等价模拟，并让观察者在至少 48 小时内分三次回山。抽查最近 20 条重点事件里触发条件、宿主行动、所得与后续用途。开出相同任务名的两次也能因性格、环境、准备与奖励产生不同结果。比较不同招徒方向能否吸引不同来人 |
| 系统成长与普通修行 | 至少 200 个配对种子观察倾向与收益分布。关闭传奇赐福时，普通修行、百艺和招徒依旧可持续。开启例外时能追到已解锁权限或稀有机缘，弱者的逆袭有事实可查。隐藏奖提前封定。明奖与后来触发的隐藏奖各自只发一次 |
| 手机与长档 | M1 在记录机型的早期档测八小时补算，p95 实验目标 ≤2 秒。M3 测百名活跃宿主离线 24 小时，p95 目标 ≤5 秒。千人含远方摘要测七日，期间可查旧纪事、可中断续算。记人数、机型、采样数与视口模拟或真机。M1 冷缓存首屏传输先以 ≤1.5 MiB 为目标 |
| 世界与发布 | 遵守 v0.7 已确认的世界尺度、寿元、品阶与阵营，未定的项目名继续留空。提交前核对真实分发资产、许可及备份。M3 至少在 iOS Safari 和 Android 真机各走一次恢复与导入，M4 用实际托管路径验证更新 |
| 失败时怎样接着做 | 私令泄露、重复发奖或旧档丢失，先保存复现档，修复并重跑同一命令序列。玩家只记得领奖数字时，先检查这份奖励在下一次行动里能不能真正用出来。每个过关版本保存构建、内容版本、独立存档与回退提交 |
