# Neon 的协作与验收规则

每项工作只指定一个实现负责人。交接的是一个可检验的问题、一个提交和一组证据。任务的解法留给实现者。世界已确认规则、存档兼容、素材来源和战报事实具有约束力。

## 最小团队

| 使用谁 | 什么时候值得用 | 输出及停止条件 |
| --- | --- | --- |
| Neon | 选择眼下最重要的玩家问题、拆一张工单、协调工作树、独立复玩或安排验收。 | 一个范围、一位实现者、一次验收结论。参与写实现时，换另一位做独立验收。 |
| Hydrogen | 默认实现者。连通内核、UI、存储和真实入口，修复普通 Bug。 | 小步提交、能复现的种子或操作、修改前后证据。简单任务可独自完成再交 Neon。 |
| DeepSeek | 接口已定、输入能单独交付的工作，如内容 lint、批量夹具、CSV 映射、统计偏差或旧档回归。可替代 Hydrogen 做一张独立票。 | 返回数据、测试或补丁。批量文案抽样读前因与后果。共享核心文件仍由一位负责人修改。 |
| 一位高级模型 | 相同缺陷经过两种有记录的修法仍复发、跨模块确定性失效、旧档损坏风险、高影响架构争议或两轮切片仍无法产生有分量的选择。 | 只请一位给根因／取舍及可证伪预测。Astra 可做设计复核，Argon/Opus 任选其一看关键难题。Carbon 等付费 API 仅在具体任务有优势且本次预算已获授权时使用。 |

额度与模型名取自本轮用户提供的可用资源，实际跨平台调用权和余额由当前平台决定。默认一名写代码、一名验收。确有互不相交的任务才让第二名实现者开独立工作树，同时活跃实现者最多两名。Neon 验明任务入口才派工。豆包上的 Kimi／DeepSeek／Qwen 可替代独立小票，不叠加常设岗。GPT Plus／Claude Pro、少量 Argon/Opus 保留给关键复核。Vertex 的 429 和远端模型均不进入游戏运行依赖。

每张任务单传目标、范围、版本、相关文件、一个失败样例、完成标准和回退点。起步约一页上下文、3～5 个必读文件，需要更多时指出依赖。每项付费调用预先记上限、预计次数、停止条件和替代路径。本轮实际操作限于检索和本地验证。用户提到的 Carbon 约 €10 仅是账户背景，使用前按任务确定金额。没有跨平台调用能力时，Neon 在仓库落任务单与基线提交，由可访问该平台的人转交，再收回分支／补丁、测试命令和证据路径。未实际收到结果的工单标记“待转交”。

## 让反馈跟着事件走

1. **设计时触发。** 凡新增可见事件或玩家交互，在工单 `feedback` 登记事件 ID、重要性、渠道、理由。普通交互可只给选中／文字反馈。重要关系变化优先让当事人同框。重大突破可加一声与一幅短特效。登记“文字已足够”即可闭合这项判断。
2. **需要声音时触发。** 搜本地清单、试听并记候选。没有匹配再走 sfx 搜索，其次 Soundza 搜索，再评估 Soundza 生成。视觉同理，先查已有图集，再用 Arcadia，更复杂的重要画面才用 AetherFX。已选好素材后结束搜索。工具在启动时做一次真实样例探测，票内记录协议、名称、输入、返回 ID 或错误、使用范围。失败时保留降级的文字／头像，授权内的其他工作照常推进。[本机能力证据与 Skills 路由](assets-tools.md)
3. **接入时触发。** 反馈绑定 `factId / cueId / assetId / offsetMs / licenseRef`。由同一个播放起点调度文字、声音、帧图。移动端首次交互后解锁声音。回归汇总折叠重复音，按需播放标记事件。静音、减弱动态、切后台、重复展开均保留同一结果。导出图集元数据决定帧数，尾格为空时不播放。[浏览器音频播放条件](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)
4. **提交时触发。** 工单检查器会拒绝没有理由的反馈、无事件 ID、以及缺素材 ID／许可／偏移的声音或特效。M1 的产品构建再校验引用文件存在、源资产可用于目标发布范围、图集切片合法。高等级演出核对画面转折、音效起点、字幕和跳过，建议误差不超过 100ms。普通静态界面无需调用生成工具。

## 已可执行的 M1 工单

项目有一张 [Neon 工单](neon-m1.json) 和一个零依赖 [检查器](../../tools/check-handoff.mjs)。从仓库根运行。第一条校验人员、目标及反馈设计并列出待补材料。第二条用于实现完成后检查是否具备独立复玩条件。当前计划可以通过第一条，第二条应因七项证据空缺而返回非零。

```powershell
node tools/check-handoff.mjs
node tools/check-handoff.mjs docs/plan/neon-m1.json --accept
```

修改工单检查器后运行 `node --test tools/check-handoff.test.mjs`。已在本机 Node 24.22.0 运行。八组用例覆盖缺证据、可接受的分叉、断链、换种子、相同后继、错误截图类型、同图冒充两种视口，以及声音缺少许可／时间绑定。它们只验检查器自身。

Neon 在功能分支上填写七个仓库相对路径。两项政策 JSON 取自实际模拟导出。`checks` 记录提交号、命令、构建与测试结果。`trace` 为实际浏览器操作的 ZIP。`mobile/desktop` 为产品可玩页面截图。`playtest` 记录独立试玩、玩家原话及未过项。规划校样和合成检查器夹具不能充任产品证据。图片／ZIP 的签名只验证文件类型，验收者仍须打开文件、对照实际提交复玩。

每份政策导出包含字符串 `seed, rulesVersion, contentVersion, rngVersion`、正整数 `endTick` 和两个 SHA-256。用相同的规范化序列化计算 `startHash`（政策生效前全域快照）和 `commonInputsHash`（有序外部输入，仅把指定位置的单个政策值换成同一占位符）。分支值分别为 `policy: relief`、`policy: survey`。导出 `nextOpportunity` 及按父因排好的 `chain`，首项为 `{id, kind: policy_applied, value}`，中间项带 `{id, parents}`，末项为 `{id, parents, kind: opportunity_opened, opportunityId}`。这些是可移植的验收投影，事实仍保存在各自存档。检查器比较起点、输入、版本、结束刻、因果和后继。独立者再核对原档与 UI。

## 在开发中落地

| 自动化负责的事 | 由谁、何时、怎样确认 |
| --- | --- |
| 缺字段／资源／译文、引用断裂、罕见规则漏条件 | 内容提交即跑 Schema、引用和正反例。首版可用 JSON Schema + Ajv。现有表只加内容，新增操作需附规则测试。[Ajv](https://ajv.js.org/guide/getting-started.html) |
| 负库存、重复发奖、乱序、离在线不同、迁移损失、战报不符 | PR 跑 Vitest 的固定种子、历史黄金档及性质测试。随机失败保存最小种子与命令。概率分布每天或合并前批跑，区分规则故障和体验调参。[Vitest](https://vitest.dev/guide/) · [fast-check](https://fast-check.dev/docs/introduction/) |
| 入口断、掉帧、渲染错误、移动溢出、反馈打断模拟 | Playwright 从正式启动入口跑导航、读档、离线归来、政策分叉、反复展阅。留 trace、两尺寸截图、控制台／网络错误和耗时。构建成功后再用产物重走主路径。[Trace Viewer](https://playwright.dev/docs/trace-viewer) |
| 人物可信吗、普通弟子值得记吗、下一次想看谁 | 独立验收者先盲玩再看种子。记录预期、实际、改变想法的那句话和下一次决定。真人观察按 [M1/M2 标准](roadmap.md)进行。模型的解释或测试绿灯只覆盖各自验证过的部分。 |

**仓库接力。** 当前任务与证据索引在工单，架构决定在对应文档，失败复现和下一项优先工作随任务提交。正式开发后，Neon 维护一张短状态表（最近稳定提交、当前票、已知问题、下一票）和按票归档的证据。同一信息只维护一份。交接用“提案／已读／已装／已调用／已实现／测试通过／独立试玩／真人观察”标明事实等级，可直接链接文件、日志、截图或原话。设备、时间倍率、种子、规则版本和提交写进证据。

**修复与回退。** 实现者先最小复现、修复、复测原种子和邻模块。同一原因复发则暂停扩张。重大改架构需记当前瓶颈、候选收益、代价、失败门槛和回退提交。每个独立功能测试后提交，整合前 Neon 核对分支与工作树。保持用户现有改动和备份。存档迁移、依赖升级和批量资源操作前另存可恢复的检查点。稳定版本的 Git 引用、旧档和素材来源均需保留。体验刚好过线时也无需例行再找几位高级模型重审。

**备份责任。** 新增或替换资产包时，素材维护者更新包哈希和来源，独立介质备份后抽取一个文件验证可恢复。配置分开保存可提交的默认项及私有本机项。凭据交由原有凭据管理方式保管。每次改档前留一份旧版可导入的独立导出，升级后用新槽演练一次。交接表只记备份位置或凭据引用，不写密钥和真实玩家存档内容。
