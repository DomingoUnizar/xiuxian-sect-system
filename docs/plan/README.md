# Neon 开工入口

**第一件要做的事，是让同一个药谷在两种宗门政策下，长出两段不同的人生。** 玩家只有一份奖赏，可以资助山口接应，也可以资助入谷取样。弟子自己决定是否接下委托。下次回来，玩家要能看懂谁回来了、谁欠了人情，以及为什么下一次出谷的人选变了。

本轮交付设计、技术决策、两幅实际浏览器排版校样和开发验收方案。游戏代码、可玩入口、存档和真人试玩均在后续里程碑。文中的人数、权重、时长和性能数字是首轮实验参数，Neon 可以根据证据调整。

## 给 Neon 的第一张任务单

本轮结束时，`main` 指向四份原始文件的基线 `d6dec06`，规划保存在 `plan/neon-roadmap`。该基线证明资料可恢复，首个可玩稳定版将在 M1 验收后产生。开工时先执行 `git status --short --branch`、`git worktree list`、`git log -3 --oneline --decorate`。从包含本规划的提交开功能分支。下面的命令适用于分支和相邻目录尚未被占用的工作区。

```powershell
git worktree add -b feat/valley-slice '..\修仙-药谷切片' plan/neon-roadmap
```

| N1 固定一个出发点 | Hydrogen 建立六人快照、单一药包、单一委托赏额、两处地点、一个预报窗口。先在无 UI 环境运行 `advance`，让无委托的弟子也会工作、休息。 | 保存初态、种子与规则版本。验证重复推进、空闲行为、委托拒绝、同一药包不能被双方领取。 |
| N2 接通第一次后果 | 在同一引擎上接入两项政策、一次自动遭遇和一条后续传路机会。同一次事务写入战斗、伤势、物资、关系与因果引用。 | 同一初态仅改政策的两个导出档至少有一项长期差异。能追到实际事件。重复展阅和刷新三次，胜负、物资与关系保持一致。 |
| N3 做成能玩的短局 | 接上山门近况、人物志、政策选择和回归纪事。实施离线推进、保守默认和本地存读。选取现成青玉组件、两幅场景和少数头像。 | 从普通入口完成“看人 → 选政策 → 放手 → 回归 → 凭后果再选”。保留桌面／手机截图、短 trace、两档和实际时钟区间。 |
| N4 交给独立验收 | Neon 在干净副本按 [M1 盲测](roadmap.md)复玩。实现者修普通故障。缺人试玩时，登记已经验证的系统行为，把乐趣结论留在待测栏。 | 交付能复玩的入口、提交号、观察记录、失败种子及回退点。若玩家解释不了为什么回来，先改这一个循环，再开放扩张。 |

**可直接转交给 Neon**

> 从 `plan/neon-roadmap` 开独立工作树，读取本页和 N0～N4 涉及的章节。用六名弟子和一次药谷历练，证明玩家的一个间接决定能在离线后改变人物关系，并开启不同的后续机会。先做到 M0，沿同一实现完成 M1。世界规则按 v0.7，战报按 V0.2。复用已有美术，用同种子双档和真实浏览器留下证据。实现方式可调整。每个独立功能验收后提交，按仓库任务单交接。乐趣门槛通过后再扩展内容。

## 本轮的恢复点

四份原稿的字节基线是 `d6dec06`，工单与检查器提交为 `918a166`，规划与校样是随后的文档提交。要核对原稿，可在空的相邻路径运行 `git worktree add --detach '..\修仙-原稿核对' d6dec06`。需要撤销本轮成果时，在干净的回退分支按“规划提交、检查器提交”的顺序运行 `git revert --no-edit` 并传入这两个提交号。已有后续工作时先在独立工作树检查依赖。
